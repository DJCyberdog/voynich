## Windows: neuer separater Testordner

Entpacke das private Owner-Testpaket vollständig in einen neuen Ordner. Kein bestehender Workspace wird aktualisiert. Das Paket enthaelt die gepinnten App-Quellen, Originaldaten, lokalen Vorschau-Katalog, Teilinventare, Modelle und das vorbereitete Manifest. Keine registrierten Runs, keine Review-Entscheidungen, keine Freigaben fuer Klassifikation, keine Zugangsdaten. Quell- und Datenrechte bitte vor der Nutzung selbst prüfen. Keine weitere Verteilung dieses privaten Pakets.

1. In PowerShell im App-Ordner `Voynich Research Studio`: eine vertrauenswuerdige vollstaendige Windows-x64-Installation von CPython 3.13 mit Tcl/Tk, venv und ensurepip ist Voraussetzung. Falls `py -3.13` nicht verfuegbar ist, den absoluten Pfad zur entsprechenden python.exe verwenden. Das kleine Setup bezieht die Dependency-Assets lokal; weder Python noch Torch sind im Download enthalten. Kein Admin erforderlich, kein globales pip install. Profil muss zum vorbereiteten Run passen (siehe `data/rc1/trial/run.json`).
2. CPU: `py -3.13 -E -s -B vrs_rc1_trial.py bootstrap . --profile cpu`. Fuer ein separat vorbereitetes CUDA-Testpaket stattdessen `--profile cuda`. Der explizite Befehl baut aus dem vertrauenswuerdigen lokalen Python einen Bootstrap und laedt Wheels von PyPI/PyTorch; er erzeugt einen Lock mit Hashes, genehmigt ihn aber nicht. Laufwerkplatz und Netzwerk erforderlich, besonders fuer CUDA. Die NVIDIA-Treiber-/CUDA-Faehigkeit wird in Setup geprueft; kein CPU-Fallback eines CUDA-Runs.
3. `config/install-cpu.json` beziehungsweise `config/install-cuda.json` und Herkunft/Lizenzen pruefen. Den ausgegebenen `sha256` des Installationsplans bewusst freigeben: `./Setup.bat --profile cpu --plan config/install-cpu.json --approve <SHA256>` (oder `cuda` in beiden Stellen). Platzhalter durch echten Hash ersetzen. Setup installiert ausschließlich lokale Laufzeit und gehashte Wheels und fuehrt den Smoke-Test aus. Keine Zertifizierung der Runtime durch bloße Hashbildung.
4. Den vorbereiteten lokalen Datenplan pruefen: `./.venv/cpu/Scripts/python.exe -E -s -B vrs_rc1_intake.py verify . --scope REAL_RESEARCH --approve <plan_sha256 aus config/rc1-admission.json>` (bei CUDA `cuda` statt `cpu`). Das bestaetigt bytegenaue lokale Aufnahme, keine wissenschaftliche Anerkennung. Keine Ausfuehrung, wenn Rechte, Hashes oder Quelle unklar sind.
5. `./Start.bat` startet die GUI. Unter **Quellen** das vorbereitete Manifest `data/rc1/trial/run.json` waehlen, pruefen und explizit registrieren. Unter **Jobs** den lokalen Worker starten. Im **Glyphen-Review** Ausschnitt/Referenzen und Teilinventare ansehen, einen Entwurf erstellen und eine bewusste Testentscheidung treffen (z.B. zurueckstellen). Die erste Seite kann viele ueberlappende Vorschlaege erzeugen. Das ist keine Anzahl echter Glyphen. Nicht alle Vorschlaege fuer einen UI-Test manuell bearbeiten.
6. Worker ueber Jobs oder `./Stop.bat` kooperativ stoppen; GUI separat schliessen. Neustart, Review-Revision und unveraenderte Daten testen. Wenn Fehler auftreten: Protokolle/Diagnose lokal pruefen; keine private Glyphenentscheidung, Originaldaten oder Zugangsdaten hochladen. Native Owner-CUDA-, HiDPI-, Tray-, Nicht-Admin- und weitere praktische Gates bleiben gesondert zu qualifizieren.

## Neue private Testaufnahme aus Originalen (Entwicklung)

Die CLI `vrs_rc1_trial.py stage ORIGINALS NEW_INTAKE --source APP` akzeptiert nur bekannte exakte Dateien; `ZL3b-n.txt` und `voynich(1).pdf` sind reine Dateinamen-Aliasse. Ein LFS-Pointer wird als Hash-/Groessenabweichung zurueckgewiesen. `attest INTAKE sources-plan.json --approve HASH --basis "konkrete lokale Nutzungsgrundlage"` bindet eine ausdrueckliche Erklaerung an die vorhandenen Originale (keine Aussage ueber Rechte Dritter). `prepare INTAKE sources-approved.json NEW_TRIAL --approve HASH --backend cpu|cuda` erstellt Vorschau, Teilinventare und neuen Run-Plan. Die neue Planidentitaet separat pruefen und mit `vrs_rc1_intake.py provision NEW_TRIAL rc1-trial-plan.json NEW_APP --source APP --approve NEUER_HASH --scope REAL_RESEARCH` in eine neue private Kopie aufnehmen; absolute Pfade zum Plan verwenden. Keine automatische Registrierung oder Modellerlaubnis. Der Owner-Test ist keine Freigabe von RC1-05/G1-G8, keine Manuskriptentschluesselung und keine behauptete native CUDA-Abnahme.
