## Implementation and contract

- New vrs_exceptions.py uses the existing schema-1 Ledger transaction/validation interface, three additive versioned SQLite tables, no edits to alpha.1 coordinator or ledger code/identity. A partial or unknown extension schema is rejected. Existing runs and receipts are preserved.
- Explicit seed from an unlocked run with a completed, hash-pinned classification receipt. Initial import is only allowed with READY control and PENDING exception review. All rows, snapshot and history entry commit together; replay verifies exact content without duplication. Concurrency serialized by the actual SQLite BEGIN IMMEDIATE transaction. No network or outbox action.
- OCCURRENCE_OUTCOMES_V1 classification index is the proposed VRS-096 producer contract: schema/run/stage/status, segmentation reference, model/policy/reference hashes and ordered page outcome references. Per-page file contains schema/run/page, corresponding segmentation-page reference and rows {region_id,box,outcome,reason,uncertainty}. Outcome ACCEPTED/NONE, FAILED/PROCESSING_ERROR, or ABSTAINED with one of UNKNOWN, LOW_CONFIDENCE, OUT_OF_DISTRIBUTION, UNSUPPORTED_INVENTORY, AMBIGUOUS_SEGMENTATION, COMPOUND_SEGMENTATION, CONFLICT. Uncertainty nullable or finite numeric [0,1]; it is metadata, not a validated threshold or calibration. This envelope carries occurrence outcomes, not accepted label mappings; future producer must retain those in separate pinned evidence.
- Validate full page/region/box membership against alpha.1 proposal structure, crop hashes, geometry bounds, policy/model/reference binding and exact classification denominator. Only abstentions enter queue. Accepted and failed occurrences are counted separately and remain in source outcomes. Identical crop bytes at distinct occurrences or in independent runs do not collapse. Stable IDs bind run, page, region, crop reference and box. Order follows source segmentation, not arbitrary classifier order. Missing/extra/duplicate outcomes fail closed.
- Summary reports pending/resolved/deferred counts, immutable snapshot hash, dependent stage transcription_alignment and WAITING_FOR_REVIEW or NO_EXCEPTIONS. All entries are PENDING in this increment; no resolve/defer mutation or automatic alignment authorization. A zero queue does not establish recognition accuracy or erase classification failures. Run control and stage receipts are deliberately not changed. Alpha.3 must connect real review-pending parking, independent-run advancement and safe gate checks; VRS-097 owns authorized correction and wakeup.
- Paginated local CLI/API returns source-bound exception geometry and metadata. Summary checks classification receipt, top-level artifact and stored queue digest; item reads additionally verify returned crop bytes. Full nested source revalidation occurs on seed/replay, not every summary. Future dependency handoff must revalidate via seed/replay, not trust a display snapshot alone. Reads currently scan the stored queue digest; page JSON limited to 32 MiB, fail explicitly on excess; representative manuscript scaling not benchmarked.
- All persisted paths are root-relative and the queue shares workspace/vrs095/ledger.sqlite; local trusted workspace, no remote executable inputs or scientific promotion. Source hashes do not substitute for the independently validated recognition policy. No publication of private contents.
