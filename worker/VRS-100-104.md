# VRS 0.10.0 — VRS-100–104 desktop foundation

Status: local implementation, partial technical acceptance; not native/release/scientific acceptance. Parent a0e35d564f19b56fe7111355e513adb4a2eb3e90. Existing compute/runtime and decision authority are preserved unchanged.

## Architecture and scope

Tk/ttk is selected for a lightweight native desktop baseline; Pillow provides raster display. Tk is distributed with compatible Python/Tcl/Tk installations, and Pillow is already in requirements-review.txt. No Qt/web engine or ML dependency added to the review process. Python/Tcl/Tk/Pillow redistribution/license inventory and portable installer acceptance remain VRS-130 work. Optional PDF operations use existing PyMuPDF compute dependency; not required for ordinary review. Existing Python runtime, PDF tooling, inventories and prototype models are not replaced by this UI.

- **VRS-100:** dark/light design tokens, sidebar, paned canvas/reference layout and responsive controls; actual GUI tested at 1280x800 and 1024x650 under Xvfb. Native Windows HiDPI/accessibility and representative minimum-hardware profiling still open.
- **VRS-101:** Home with actual registered runs/stages, workspace switch, local project settings, language/theme switching, persistent window geometry, error/empty states and worker configuration. English and German primary navigation; internal state codes and some controls remain English. Layout persistence currently window geometry, not all pane positions. No auto discovery or auto startup.
- **VRS-102:** actual abstention queue from read-only SQLite, verified local crop bytes, context/glyph toggle, bounded zoom, panning, pagination, selected box geometry, shortcuts. No classifier suggestion or owner key displayed in the review pane. No independently validated blind-study isolation claimed; separate curator-controlled blind workflow remains. Compound geometry is not resegmented by this version.
- **VRS-103:** independently selected convention, visual reference scheme, label filtering, lazy sample image loading with pinned hash, source/version/coverage/preview indicators. Explicit per-inventory mapped/absent/unknown choices; false positive, compound and deferred choices. No automatic label conversion across visual and runtime conventions. Immutable local draft keyed by decision digest; authoritative revision checks and wakeup still via runtime CLI. Offline drafts can be explicitly submitted later. Actual independently verified EVA/STA1 catalog content and full adjudication workflows not established by synthetic tests.
- **VRS-104:** copy local PDF/text/JSON sources into app-owned content-addressed storage, source registry with SHA256 verification, validate PDF and local transcription, generate new fixed-scope run manifests with pinned existing source bundles; verify manifest and explicitly register via runtime. Build reference catalogs from local PDF and explicit plan; preview clearly distinct from reviewed catalog. No automatic catalog approval; invalid source/plan/image blocked. Manifest builder currently exposes up to two transcription slots; existing prebuilt manifests may be verified/registered. No download, remote publication or training. Source assets stay local.

Desktop API uses read-only SQLite mode/query_only and does not write ledger state. Expensive reads/import and authorized CLI calls are dispatched from the Tk event loop to a single executor. UI renders bounded local images. Local workspace trust remains the same as v0.9.6; these are not a general malicious-files sandbox. Registered source bytes and decision revisions are checked by the existing authoritative runtime; source hashes alone do not prove scientific validity. Offline drafts do not change the run until explicitly submitted. Compute interpreter is an explicitly configured local path; portable relative-runtime resolution and full environment creation remain VRS-130. No worker startup or tray features in this package.

## Running the local development build

From worker/:

`python vrs_desktop.py ROOT`

ROOT is an existing local application/workspace directory. For review, use Python with Tk and Pillow. Set reviewer identity and explicitly select compatible compute Python in Settings for registration/decision submission. Existing VRS-096/097 run/model/inventory/approval contracts remain required. Import/manifest/catalog creation that parses PDFs requires PyMuPDF. Start existing coordinator separately for actual work. See VRS-096-097.md. The GUI does not start jobs by itself or claim calibrated real-manuscript recognition.
