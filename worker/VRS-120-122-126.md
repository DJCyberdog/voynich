## VRS-126 — controlled learning and model selection

- Explicit plan hash allowlisted by owner in config/vrs120-training.json before fitting. Candidate trained by fixed equal-weight means of agreed train features (original glyphs.py 32x32 feature extraction, float32); actual selected manual corrections included. This is batch retraining, not online self-learning. No threshold search. Conservative frozen limits include distance <= .12, margin >= .005, minimum accepted count, maximum selective risk and minimum coverage. Advisory RAM/VRAM/disk admission, not hard quotas; no arbitrary backend switching.
- Exclusive reservation in workspace/vrs120 keyed by exact manuscript and inventory hashes before training/scoring. No second evaluation in same workspace for same source/convention even if calibration fails or a process dies. Calibration must meet gate before holdout is scored. Replay may reproduce frozen results without choosing a new candidate. One-shot reservation is local operational guard; it does not prevent a workspace owner from copying/deleting data, inspecting labels, changing source bytes, or tuning using outside knowledge. Independent study design and holdout isolation remain necessary.
- Total/eligible/excluded, accepted/abstained, correct/errors, coverage, selective risk and accuracy including abstentions separately retained. Unknown/false-positive truth included in evaluation denominator. Gate requires candidate noninferior in coverage/risk versus baseline and frozen minimum accepted, coverage and risk bounds. This is a technical eligibility check, not statistical significance, calibrated probability, real manuscript improvement or scientific acceptance.
- Candidate remains isolated; report status ELIGIBLE_FOR_MANUAL_REVIEW or NOT_MET. Explicit report hash allowlisted in config/vrs120-approved.json plus local metric/provenance checks for selection. Append-only local selection/rollback history and bundle_entry for future run manifest (model/report binding). No automatic replacement of models, no editing config/vrs096-approved.json, no automatic activation, no existing run mutation. Selection currently one report history per workspace; future explicit migration required for a different candidate. Actual runtime recognition approval remains independent VRS-096 policy. User must explicitly construct a compatible new manifest/model bundle and obtain any new recognition approval. No GUI learning workflow yet.
