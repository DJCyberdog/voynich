## Private app snapshot and rollback preparation

`python vrs_rc_snapshot.py snapshot APP_ROOT NEW_BACKUP_DIR --private-local` creates an exact byte inventory of a stopped disposable app (all files and empty directories, except the three shared transient lock files). Keep the emitted SHA-256 separately. `verify BACKUP --approve SHA256 --private-local` checks exact payload and ledger; `restore BACKUP NEW_RESTORE_DIR --approve SHA256 --private-local` materializes a fresh app under NEW_RESTORE_DIR/app, without overwriting the source or any existing destination. A restored portable environment needs offline Repair before use. Stop GUI, workers, publisher and all unmanaged writers first; shared locks fence normal managed execution, not hostile concurrent writers. Snapshots contain private data and may include encrypted credentials; never publish, do not share, use a private local disk with restrictive ACLs. DPAPI is still bound to the Windows user/machine; no credential portability promised. Byte inventory is not an ACL/ADS/timestamp/OS snapshot. Links, hardlinks, Git checkouts, special files, sidecars, active ownership, tampering and case collisions are refused. Limits 64 GiB / 250,000 entries. No data rewriting or source identity migration; exact rollback is restoration into a new path. Actual immutable 0.13.x source upgrade/rollback and installed Review repair PASS on hosted CI. Real private workspace/older legacy fixtures and complete release qualification remain open.
