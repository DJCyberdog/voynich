Status: PLANNED; owner-authorized requirement after 0.14.1 closure, not a production import or release. First frozen candidate target: 0.14.1-rc.1. No automatic network, publication, training, scientific promotion, or arbitrary schema conversion.

## S-tier implementation and entry gates

1. **RC1-01 source inventory / admission.** Enumerate actual locally available source files and stable IDs; canonical path, exact SHA-256, byte length, origin/version, license/redistribution status and intended role. Separate Yale original digital manuscript, independent transcription editions (Takahashi/EVA, STA/STA1, other explicit source identities), reference PDFs/crops, physical folio mapping, reviewed recognition policy/model and eligible historical artifacts. Do not conflate EVA and STA or label any preview catalogue authentic/validated. Missing, ambiguous, unlicensed, unverified or inaccessible inputs are explicitly BLOCKED; source availability alone does not certify rights or accuracy. Original PDFs and transcription files may need to be supplied locally; do not assume public repo contains them.
2. **RC1-02 explicit production provisioning.** Implement a read-only preflight plus explicit local owner approval of a hash-bound manifest, then provision a new private root from exact inputs with collision refusal, no overwrite, pinned source registry, catalog provenance, and independently reviewable missing-input report. Reuse existing Desktop/Runtime contracts, no second research architecture. Separate synthetic fixtures and blind holdout/owner-key artifacts; never inject synthetic examples into production or leak blinded keys, private source or credentials into CI/repo/package/logs.
3. **RC1-03 operational qualification.** On a disposable copy first, exercise real-source ingestion, reviewed manifest, CPU and actual owner CUDA/Review, exception queue, draft and authorized final decision, exact restart/replay and unrelated work continuation. Only explicitly approved run scope and recognition policy; default abstention for uncertified crops. If an authentic catalogue or physical mapping is incomplete, support honest manual/unknown dispositions without automatically accepting it. No forced experimental run; EXP-0038g NOT_MET and K-0001 deferral unchanged.
4. **RC1-04 migration to 1.0.** Create private full-app snapshot and separately recorded approved manifest hash; verify exact bytes, inputs, ledger, source/review/model identity, decision revisions, receipts, outbox state and artifact hashes across RC maintenance and 1.0 upgrade on a copy. Existing decisions must survive compatible upgrade; changed worker identities are fenced until separately approved migration. No automatic relabeling, overwrites, re-review or re-execution of completed evidence. If schema/identity cannot be preserved, BLOCKED with explicit safe migration or rollback; never claim general migration from synthetic fixtures alone.
5. **RC1-05 release evidence.** Frozen source commit and versioned artifacts, exact manifest and distribution digests, source rights/redistribution evidence, SBOM, release notes, G1–G8 and VRS-116; owner practical/independent UX/HiDPI and native CPU/CUDA/Review/Tray/minimum-profile tests still binding. Production workspace readiness is distinct from stable release and scientific acceptance. RC2 only if defects require it. No signed release or merged branch implied.
